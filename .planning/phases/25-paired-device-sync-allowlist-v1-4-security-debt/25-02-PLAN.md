<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN peer → transport | Discovered peer's `discoveryInfo["iid"]` and invite `context` are UNTRUSTED, unauthenticated, pre-session LAN input. |
| Pairing candidate → local store | A session that forms in pairing mode is a *candidate*, not yet trusted; no data may flow until trust is persisted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Spoofing/Tampering | browser foundPeer + advertiser didReceiveInvitation | mitigate | Both gate via PeerAllowlistPolicy.shouldConnect BEFORE a session forms; empty allowlist ⇒ nothing connects (SC-1). |
| T-25-03 | Information Disclosure | pairing-window auto-push | mitigate | Un-allowlisted candidate emits `.pairingCandidate`, not `.connected`; SyncCoordinator pushes nothing (SC-3/hole test). |
| T-25-04 | Information Disclosure | SyncSnapshot vs allowlist | mitigate | Bytes-don't-contain test proves the allowlist never serializes (SC-5). |
| T-25-05 | DoS/Tampering | discoveryInfo / context decode | mitigate | Defensive decode: nil/non-UTF8/non-UUID ⇒ untrusted, never force-unwrap; discoveryInfo kept tiny (Pitfall 2). |
| T-25-06 | Spoofing | active installID spoof | accept | Residual MEDIUM, deferred (unauthenticated pre-session channel by design); no HIGH introduced. |
